# 需求受理

## 你要产出什么

一组**标准任务要素**，作为后续规划的唯一输入：

| 要素 | 必填 | 说明 |
|---|---|---|
| 目标名称 | 是 | 地名/设施名，用于任务命名与展示 |
| 目标几何 | 是 | 点目标 `{lat,lon}`；面目标 `{coords:[[lat,lon],...]}`（≥3 顶点闭合） |
| 观测类型 | 是 | `optical` 光学 / `sar` 雷达 |
| 分辨率 | 是 | 米，数值越小越清晰 |
| 时间窗 | 是 | `windowStart` ~ `windowEnd`，ISO 格式 |
| 最大云量 | 否 | 0~1，默认 1（不限制）；光学任务建议 ≤0.3 |
| 优先级 | 否 | 常规 / 重点 / 应急 |

## 判断口径

**点目标 vs 面目标**（最容易错，错了后面全错）：

- 「某座桥 / 某栋楼 / 某个机场的塔台」→ **点目标**
- 「某城区 / 某市全域 / 某基地群 / 30×30 公里范围 / 某岛」→ **面目标，必须给多边形**

⚠️ 区域需求**绝不能简化成中心点**。简化成点会导致只拍中心一小块，用户拿到的影像远小于预期。

## 建单参数（照抄，别拼运气）

`dispatch order-intake` 的 7 个必填项，**一次给全**：

| 字段 | 示例 | 说明 |
|---|---|---|
| taskName | "嘉手纳基地光学核查-2m-7日窗" | 任务名 |
| **geomType** | `"point"` 或 `"polygon"` | **最常漏的一项** |
| geom | 点：`{"lat":26.35,"lon":127.77}`<br>面：`{"coords":[[lat,lon],...]}` | 自有结构，不是 GeoJSON |
| obsType | `"optical"` / `"sar"` | |
| resolution | `2` | 米 |
| windowStart | `"2026-11-17T00:00:00Z"` | ISO，UTC |
| windowEnd | `"2026-11-24T00:00:00Z"` | ISO，UTC |

**可选**：maxCloud（0~1，默认 1）、priority（常规/重点/应急）、isEmergency。

CLI 会在本地预检，缺项直接告诉你缺哪个并给完整示例——**照着补一次就行，不要一个个试**。

## 缺项处理

**单轮合并追问**，一次列齐所有缺项，每项给建议值，不要挤牙膏：

> 还缺 2 项：
> 1. 目标位置——请给经纬度或多边形顶点（如果是「某市全域」我按行政边界近似）
> 2. 分辨率——建议 2 米（分析级）；如需 1:1 万成图用 1 米

## 时间窗的处理

- 用户说「明天」→ 按北京时间（UTC+8）换算成 ISO
- 用户说「3 天内」→ 从当前时刻起 72 小时
- 光学任务如果时间窗只覆盖夜间（当地 20:00 之后到 06:00 前），**主动提示**：光学卫星过顶集中在当地 10:00~14:00，该窗口内大概率无可用过顶，建议改到白天或改用 SAR

## 输出

把要素整理成一句话确认给用户，然后交由「覆盖范围判定」技能继续。
