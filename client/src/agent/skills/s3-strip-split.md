# 条带拆分建单

## 使用前提

**只有「覆盖范围判定」判定「需要拆」时才用本技能。**
判定为「单星单次可完成」的任务，直接建 1 个任务，跳过本技能。

## 核心规则

> **一个任务 = 一个条带 = 一张订单 = 一颗卫星**

不是「一个任务派多张单」，而是**拆成多个独立任务**，每个任务在任务列表里独立可见、独立派单、独立跟踪。

## 拆分方法

### 沿卫星地面轨迹切（不是沿经纬线）

条带必须**平行于星下点轨迹**。北京纬度下轨迹方位角约 −10°（近正南北偏西），所以条带是**南北向长条**，沿东西方向排列。

### 宽度 = 传感器幅宽

- 不能按区域大小放大幅宽
- 用判定阶段确认的那颗星的幅宽（如 12km）
- 相邻条带留 15% 重叠，保证拼接无缝

### 长度上限

单条带沿轨长度 ≤ 100 km。超过则再分段，否则一次过顶拍不完。

## 建单

调用 `dispatch order-intake`，服务端会自动按上述规则拆分并逐条建任务：

```
dispatch order-intake '{
  "taskName": "北京市石景山区1:1万地形图",
  "targetName": "北京市石景山区",
  "geomType": "polygon",
  "geom": {"coords": [[39.95,116.15],[39.95,116.25],[39.90,116.25],[39.90,116.15]]},
  "obsType": "optical",
  "resolution": 1,
  "windowStart": "2026-11-17T00:00:00Z",
  "windowEnd": "2026-11-24T00:00:00Z",
  "maxCloud": 1,
  "priority": "重点"
}'
```

返回：
```json
{
  "ok": true, "split": true, "stripCount": 2,
  "tasks": [
    {"taskNo": "...", "stripIdx": 1, "taskName": "…-第01带（共2带）"},
    {"taskNo": "...", "stripIdx": 2, "taskName": "…-第02带（共2带）"}
  ]
}
```

## 拆完要做什么

1. **对每个子任务分别算候选**（服务端已自动串行执行）
2. **逐条汇报**：第几带、谁拍、什么时候、覆盖多少

## 汇报格式

```
【拆单结果】石景山区 → 拆为 2 个独立任务

第01带  RSBH-…-001  覆盖 100%  推荐 GAOFEN-2（长光）
第02带  RSBH-…-002  覆盖 100%  推荐 GAOFEN-1 03（资源卫星中心）

两个任务在任务列表里分别可见，可分别派单。
```

## 禁止事项

- ❌ 不要拆完仍当成一个任务派多张单
- ❌ 不要对判定为「不拆」的任务强行拆分
- ❌ 不要在拆单后只汇报总数不汇报每个任务
