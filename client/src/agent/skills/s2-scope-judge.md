# 覆盖范围判定

## 这一步解决什么

**每个任务都要先回答一个问题：这颗星一次过顶能拍完吗？**

- 能 → 不拆，1 个任务 1 张单
- 不能 → 才拆单，每个条带一个独立任务

⚠️ **不要一上来就按幅宽切条带**。这是之前的错误做法：把「石景山区」这种小区块也切成 2 条带，派了两张单，用户看不懂为什么一块地要拍两次。

## 一条命令搞定（首选）

**不要自己去查卫星清单再手算**——那会反复翻页、很容易误判（曾出现「库里只有 20 颗旧星」的错误结论）。直接用：

```bash
dispatch scope '{"coords":[[39.95,116.15],[39.95,116.25],[39.90,116.25],[39.90,116.15]],"obsType":"optical","resolution":1}'
```

返回：

```json
{
  "region": {"widthKm": 8.5, "heightKm": 5.6, "maxEdgeKm": 8.5},
  "satellites": {
    "usableCount": 87,
    "widest": {"name": "JILIN-01 KUANFU 02B 2", "operator": "长光卫星", "swathKm": 150},
    "top5BySwath": [...]
  },
  "judge": {
    "needSplit": false,
    "reason": "区域长边 8.5km ≤ 最宽可用幅宽 150km（JILIN-01 KUANFU 02B 2），单星单次可完成",
    "estStrips": 0
  },
  "nextStep": "不需拆单：直接用 dispatch order-intake 建 1 个任务"
}
```

**直接把 `judge.reason` 和 `nextStep` 转述给用户即可**，不需要再补充计算。

## 命令背后的判定流程（供理解，不必手动执行）

### 第一步：量区域尺寸

从多边形算外接矩形，取长边和短边（km）。

### 第二步：查可用卫星的幅宽

按任务要求筛出可用卫星（观测类型匹配、分辨率满足），看它们的幅宽分布：

| 典型幅宽 | 代表卫星 |
|---|---|
| 12 km | 吉林一号窄幅、高分二号部分模式 |
| 45 km | 高分二号 |
| 60 km | 高分一号 |
| 90 km | 高分六号 |
| 150 km | 吉林一号宽幅 |

### 第三步：判断

| 条件（以最宽可用星为准） | 结论 |
|---|---|
| 区域长边 ≤ 最宽幅宽 | **单星单次可完成 → 不拆** |
| 区域长边 介于 1~2 倍幅宽 | **需侧摆跨带 → 保守按拆处理** |
| 区域长边 > 2×幅宽 | **确定需要拆** |

### 第四步（关键）：算一次候选确认

**判定不能只靠几何估算**，必须实际算候选验证：

- 估算「能覆盖」→ 跑一次候选（整块区域当 1 个任务）
- 候选返回有星覆盖整块 → **确认不拆**
- 候选返回覆盖不全 → 说明估算偏乐观，**转入拆单**

## 算法依据（文献）

条带划分**没有固定公式**——它是 min(条带数) + min(总长) 的双目标 NP-hard 问题。
系统按以下文献的成熟做法实现：

| 来源 | 方法要点 |
|---|---|
| 航天东方红专利（陈雄姿等） | 边界线斜率确定方向集合，求最小条带数 + 最短总长 |
| CCDC 2026 Optimal Strip Partitioning | 目标 = 最小条带数 + 最短总长，再定扫描方向 |
| 宇航学报 2025（南航李爽等） | 自适应条带划分，提高区域与条带交并比 |
| IFAC 2026（张航宁等） | 渐进包络 PGE，贪心可达最优解 1/2 以上 |

**系统实现**：在「轨迹方位角 ± 动中成像偏角」范围内枚举候选方向，
逐个算条带数与总长，取最少者。返回的 `direction.reason` 会说明选了什么方向、为什么。

**关键物理约束**：条带方向必须与星下点轨迹平行（TDI-CCD 像移约束）。
只有敏捷星能「动中成像」偏转：
- 高分多模卫星：官方标称「与星下点轨迹任意方向推扫」
- 泰景三号04星：偏离星下点 50°
- 传统推扫星：偏角 0°

系统按可用星的敏捷比例自动决定偏角上限（侧摆 ≥35° 视为敏捷平台）：
敏捷占比 ≥50% → 10°，≥20% → 5°，否则强制 0°（平行轨迹）。

## 尺度分档（系统自动判定，不用你算）

`dispatch scope` 会给 `scale` 字段，共五档：

| scale | 含义 | 处理方式 |
|---|---|---|
| `point` | 点目标 | 不拆，1 任务 |
| `small` | 长边 ≤ 规划幅宽 | 不拆，1 任务 |
| `medium` | 幅宽 ~ 2倍幅宽 | 横向拆少量 |
| `large` | 2倍 ~ 8倍幅宽 | 拆多条带 |
| `national` | > 8倍幅宽 | 多星多期，**提示按省/区域分批** |

## 实测回归数据（10 个尺度全通过）

| 用例 | 长边 | 规划幅宽 | 尺度 | 条带 | 判定 |
|---|---|---|---|---|---|
| 点目标 | - | - | point | 0 | 不拆 |
| 单个机场 | 4.4km | 20km | small | 0 | **不拆** |
| 石景山区 | 8.5km | 20km | small | 0 | **不拆** |
| 上海主城 | 28.6km | 45km | small | 0 | **不拆** |
| 南京全域 | 154.8km | 20km | large | 12 | 拆 |
| 北京市域 | 179.1km | 45km | large | 17 | 拆 |
| 长三角 | 342.8km | 45km | large | 41 | 拆 |
| 全国 | 5558km | 45km | national | ~124 | 分批 |
| 北京 SAR 5m | 179.1km | 30km | large | 25 | 拆 |
| 北京 0.5m | 179.1km | 15km | national | 12 | 分批 |

**注意同一个北京全域，因分辨率要求不同，规划幅宽和尺度都不同**：
- 2m 光学 → 幅宽 45km → large，拆 17 条
- 5m SAR → 幅宽 30km → large，拆 25 条
- 0.5m 光学 → 幅宽 15km → national，拆 12 条但需分批

这说明**不能背固定的条带数，必须用 `dispatch scope` 实测**。

## 输出格式

```
【覆盖判定】
区域尺寸：{长边}×{短边} km
可用卫星幅宽：{最宽} km（{卫星名}）
判定：单星单次可完成 / 需要拆分为 N 条带
依据：{几何判断 + 候选验证结果}
```

## 硬性纪律

- **判定结论必须给数值依据**，不能只说「需要拆」
- 判「不拆」之前必须实际算过候选，不能凭估算
- 判「要拆」时，说明拆几条、依据哪颗星的幅宽
