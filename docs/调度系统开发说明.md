> 底座：310 颗遥感卫星星历库（`docs/数据底座说明.md`）
> 设计依据：《遥感卫星统一调度系统-开发执行逻辑说明.md》（大模型编排 + 小模型确定性计算）

## 一、系统架构

```
┌─────────────────────────────────────────────────────────────┐
│ 前端（React + three.js）                                      │
│  ├─ 三维星座态势（原有底座）                                    │
│  ├─ 调度工作台（任务/订单/直控/任务池/公司 五Tab）                 │
│  └─ AI 下单助手（Blade SDK 对话面板，右侧可拖动）                  │
├─────────────────────────────────────────────────────────────┤
│ 后端（Node + Express + SQLite）                                │
│  ├─ /api/*            底座 API（卫星/位置/轨迹/过境）             │
│  └─ /api/dispatch/*   调度 API（任务/候选/排序/派单/直控）          │
├─────────────────────────────────────────────────────────────┤
│ 算法层（全部确定性计算，可复算）                                   │
│  ├─ candidate_calc.mjs  轨道预报/可见窗/约束筛选/云量解算           │
│  ├─ priority_calc.mjs   S=Q×R×C 综合评分排序                     │
│  └─ dispatch.mjs        R1~R6分流/指令生成/独立校验                │
├─────────────────────────────────────────────────────────────┤
│ 大模型编排（Blade Agent SDK 接前端）                              │
│  └─ dispatch 业务 CLI（Python，智能体沙盒执行 → 公网API回写）        │
│     任务解析/缺项合并澄清/候选汇报/派单反馈 —— 只做理解与编排        │
└─────────────────────────────────────────────────────────────┘
```

## 二、已实现的执行逻辑（对照设计文档）

### 4.1 任务受理 ✅
- 三类入口：手工表单 / 对话下单（LLM解析） / API 推送
- 标准任务单（3.2 全字段）：任务标识/目标信息/成像要求/约束条件/管理属性
- 生成校验：字段完整性+取值合法性（位置/类型/分辨率/时间窗/云量/侧摆）
- 缺项澄清：CLI `create` 返回 needClarify + missing 清单，智能体单轮合并追问

### 4.3 候选卫星计算 ✅
- 轨道预报：SGP4（gpJson OMM 优先，legacy TLE 兜底）
- 可见窗：星下点几何（侧摆对应地面半径）+ 光照门限（太阳高度角）
- 约束筛选规则引擎：观测类型/分辨率(侧摆退化)/谱段/时间窗/侧摆/时效/云量 逐条独立判定
- 云量解算：内置模拟气象场（气候基准×月度因子+空间纹理+天气系统扰动，全确定性可复算）
- 几何修正：侧摆穿透 1/cosθ、光照因子 fsun
- 成像可用度 A = 100×(1−ceff)×fsun
- 能力缺口统计（按约束项汇总）

### 4.4 优先级计算 ✅
- S = Q×R×C（全链路期望交付质量当量）
- Q = A×fres（分辨率富余因子，对数刻度，[0.5,1]）
- R = mtime×mbak×mlook×mdead（乘性合成）
- C = 0.5·c1+0.3·c2+0.3·c3（履约率/承载余量/资源质量）
- 排序：S降序 → 数据档位 → 过顶时刻

### 4.5 派单执行 ✅
- R1~R6 固定顺序分流（应急→直控；唯一候选→指派；高要求→指派；多候选→询价；小额→抢单；其余→人工）
- 询价：同步发询价单→模拟报价→最低价承接；全部弃权→转抢单
- 抢单：任务池+有效期+先到先得
- 订单状态机：已派发→已接单→执行中→已交付→已验收/已失败（失败→重派新订单）
- 履约回写：关闭时写履约记录，EWMA(α=0.2) 更新公司履约率

### 4.6 应急直控 ✅
- 排序首顺位生成执行方案 → 值班方案确认 → 指令生成（动作时间轴：机动→稳定→预热→成像→关机）
- 机动时长公式 t=Δθ/ωmax+ωmax/α
- 独立校验器（与生成引擎分开实现）：开关机次数/转换间隔/固存/参数合法，任一不通过即驳回
- 上注前确认 → 测控弧段（模拟喀什站）→ 执行结果回写

### 4.2 资源数据管理 ◐（部分）
- 公司生态：6 家真实国内遥感运营主体（长光卫星/中国四维/航天宏图/世纪空间/资源卫星中心/卫星气象中心），卫星按系列真实归属分配
- 公司属性：报备容量/已承接/履约率(EWMA)/数据档位
- 交叉验证与质量评分 Q=F·0.3+A·0.35+C·0.15+H·0.2：底座层已做 SATCAT 交叉核验（修复10处NORAD错配），完整评分管线待扩展

## 三、大模型接入（Blade SDK）

- **模式**：SDK 接前端（模式1）——浏览器直连 Blade Agent，授权走弹窗闭环
- **业务 CLI**：`dispatch`（Python），随会话上传到智能体沙盒执行，通过应用公网地址+Blade token 回调业务 API
- **角色提示**：遥感任务下单专员——只做理解/澄清/编排，调度结论全部来自确定性计算并如实转述
- **会话配置**：solution `sat-dispatch-assistant` + skill `my/dispatch-ops`，含字段说明与命令用法

## 五、已知边界（如实说明）

1. 云量为内置模拟气象场（气候统计+确定性扰动），非真实预报场；
2. 公司报价行为为模拟（询价价格按候选序次生成），履约率随操作真实演进；
3. 测控弧段为模拟数据（喀什站固定偏移），上注后直接进入执行态；
4. KH-11/NROL 等密级侦察星无公开星历，已从底座移除；
5. 面目标条带拆分目前按经度方向均匀切分（简化），垂直航向自适应拆分待增强；
6. C 评分模型两级演进（逻辑回归校准/LightGBM）的影子对照数据积累未启动——履约记录达到量级后可挂接。
