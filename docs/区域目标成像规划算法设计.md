# 区域目标成像规划算法设计（多尺度适配）

> 2026-11-15 设计稿。依据国内外成熟方法（见文末参考文献），重构 `normalizeTaskStrips` 的
> 单一面目标拆解逻辑，使系统覆盖「单个设施 → 小区域 → 中区域 → 大区域 → 全国测绘」全尺度。

## 0. 现状问题（为什么必须重做）

当前 `server/candidate_calc.mjs: normalizeTaskStrips` 的做法：

```js
maxD = max(质心到各顶点距离)          // 外接圆半径
stripCount = ceil(maxD * 2 / swathKm) // 按外接圆直径
for i in 0..stripCount:
    lon = cLon + (i - (n-1)/2) * swathKm / (111*cos(lat))   // 沿经度（东西）排列
```

实测后果（北京全域 115.42~117.51E、39.44~41.06N）：

| 问题 | 实测数据 |
|---|---|
| 条带整体外扩 | 生成 114.98~117.95E，比实际范围两侧各多 37.5 km（压到张家口、廊坊、天津） |
| 条带方向错 | 沿经度（东西）排，而卫星过顶是南北向飞，二者垂直 |
| 条带间有缝 | 相邻间距 12.02 km > 幅宽 12 km |
| 每条带独立等过顶 | 北京 22 条带 = 22 次独立过顶，单星 3 天只能覆盖 3~5 条 |

## 1. 成熟方法调研结论

调研 8 篇代表性文献（含 AIAA/航空学报/测绘学报/国防科大专利），业界对区域目标的处理
**统一分两阶段：区域分解（decomposition）→ 条带优选/调度（selection & scheduling）**。

主流分解方法有三类，各有明确适用场景：

| 方法 | 代表文献 | 做法 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|---|
| **固定宽度条带法** | 余婧 2015（航天五院）；老式通用做法 | 按幅宽把区域切成等宽平行条带，用 direction/offset 控制 | 简单、快 | 未考虑侧摆时幅宽变化、精度受限 | 中小区域、快速估算 |
| **网格法** | Morrison 1973 起；Zhu 2019；伍国华 2026（六边形双层网格） | 区域离散成网格点/网格单元，统计覆盖 | 精度高、可处理任意形状 | 计算量大，依赖网格密度 | 精度优先、复杂形状 |
| **动态投影条带法** | Mu 2026（北理工，离散投影动态条带）；余婧 2015（视场角随姿态扫描） | 在每个成像窗口内构造以质心为原点的平面投影，按卫星当前侧摆角动态生成候选条带 | 贴合轨道走向、可同时优化侧摆/俯仰 | 计算复杂 | 敏捷卫星、大区域 |

**关键工程约束**（文献明确给出）：
1. **条带必须平行于卫星地面轨迹**，而不是平行于经纬线。这是本系统最根本的错误。
2. **相邻条带必须重叠**：0.46m 分辨率下重叠宽度阈值 ≥28 像素（军港/机场/海岛 ≥31 像素），
   工程上一般取 10~20% 重叠率（许越 2017）。
3. **同轨多条带拼幅**（余婧 2015）：敏捷卫星可在一次过顶内通过侧摆切换多个条带，
   但受姿态机动时间约束（ΔT = 机动时间 ΔV + 稳定时间 ΔS）。
4. **侧摆会降低分辨率**：有效分辨率 = GSD / cos(侧摆角)，大侧摆还导致 MTF 退化（汪巧萍 2022）。
5. **敏捷卫星可同时调滚转（roll）与俯仰（pitch）**，VTW 内存在多个可行 OTW（Wang 2020 综述）。

## 2. 新算法设计

### 2.1 总体流程（六步）

```
输入：目标多边形 + 分辨率要求 + 时间窗 + 星座资源
  ↓
① 尺度判定    按区域尺寸选策略（设施/小/中/大/全国）
  ↓
② 投影建系    以区域质心为原点建局部平面投影（避免经纬度换算误差）
  ↓
③ 方向确定    取该区域上方可用卫星的地面轨迹平均方位角作条带方向
  ↓
④ 条带生成    沿垂直轨迹方向按「有效幅宽×(1-重叠率)」推进，裁剪到多边形内
  ↓
⑤ 条带分派    每条带匹配可见卫星与过顶时刻（保留现有 computeVisibleWindows）
  ↓
⑥ 覆盖计划    输出每条带的：谁拍/何时/侧摆角/预计分辨率/覆盖率/缺口
```

### 2.2 ① 尺度判定与策略选择

| 尺度 | 区域最大边 | 策略 | 说明 |
|---|---|---|---|
| **设施级** | ≤ 10 km | 单条带（点目标） | 一次过顶一张景，不拆 |
| **小区域** | 10~50 km | 单/双条带 | 可一次过顶完成 |
| **中区域** | 50~300 km | 条带族（同轨拼幅优先） | 优先单星一次过顶多带侧摆 |
| **大区域** | 300~2000 km | 条带族 + 多星分派 | 按星分工，长窗口 |
| **全国/超大** | > 2000 km | 网格化 + 多星多期 | 明确告知需 N 天 N 星 |

判定用**外接矩形长边**，不用外接圆直径（外接圆会显著放大，见现状问题）。

### 2.3 ② 投影建系（关键改进）

以质心 (φ₀, λ₀) 为原点，等距圆柱局部投影：

```
x = R · (λ - λ₀) · cos(φ₀)      // 东向 km
y = R · (φ - φ₀)                // 北向 km
```

所有条带计算都在这个平面里做，最后再反算回经纬度。这样：
- 消除 `111·cos(lat)` 近似带来的 0.02 km 缝隙
- 条带宽度在局部平面内是常数，重叠率可精确控制

### 2.4 ③ 方向确定（核心修正）

**条带方向 = 该区域上空可用卫星的地面轨迹方位角**。

做法：对候选卫星各取一次过顶，计算该时刻星下点速度方向（方位角 ψ），
取加权平均（按可用过顶次数加权）。若多星方向差异大（>15°），则按方向分组，
每组生成一套条带方案，最后择优。

简化实现（首版）：取该纬度太阳同步轨道卫星的**近南北向轨迹**，方位角取
`ψ ≈ 0°（正北）` 加少量轨道倾角修正：

```
ψ = arccos(cos(i) / cos(φ))     // 太阳同步轨道在纬度 φ 处的轨迹方位角
```

北京（φ=40.25°，i≈97.9°）→ 轨迹接近正南北，略微倾斜。

### 2.5 ④ 条带生成（沿垂直轨迹方向推进）

在局部平面内，把多边形旋转 −ψ（使轨迹方向对齐 y 轴），然后：

```
有效幅宽 W_eff = swathKm / cos(θ_slew)      // 侧摆时地面幅宽投影
步进 Δ = W_eff × (1 - overlapRate)          // overlapRate 取 0.15
从 x_min 到 x_max，每次推进 Δ，生成一条宽度 W_eff 的条带
每条带裁剪到多边形边界内（得到该带的 y 范围）
```

**重叠率取值**：默认 15%（文献建议 10~20%，28 像素阈值对应 0.46m 约 13m，
按 12km 幅宽折算约 0.1%，故 15% 有充足裕度；高价值目标可提到 20%）。

### 2.6 ⑤ 条带分派（复用现有能力）

每条带仍走现有 `computeVisibleWindows`，但改进两点：

1. **同一过顶内的条带聚合**：若同一条带的多个条带落在同一颗星的同一次过顶内，
   标记为「同轨拼幅组」，检查姿态机动时间是否满足：
   `ΔT = |θ_i - θ_j| / slewRate + 稳定时间 ≤ 两带间隔时间`
2. **单轨时长约束**：一次过顶可连续成像的时长受星上存储限制
   （128GB 下 0.8m 约 3.8 分钟 ≈ 1565 km），超出则拆分到下次过顶。

### 2.8 各尺度预期结果（基于实测轨道数据）

| 尺度 | 区域 | 条带数(12km/15%重叠) | 单星能否一次过顶 | 需星数 | 估时 |
|---|---|---|---|---|---|
| 设施 | 5×5 km | 1 | ✅ | 1 | 1 天 |
| 小区域 | 30×30 km | 3 | ✅（同轨拼幅） | 1 | 1 天 |
| 中区域 | 北京 178×180 km | 16~17 | ⚠️ 需 3~4 条/次过顶 | 1~2 | 2~4 天 |
| 大区域 | 京津冀 400×500 km | 39 | ❌ | 3~5 | 7~14 天 |
| 全国 | 5200×5500 km | ~433（12km） | ❌ | 多星 | 60~120 天 |

> 全国测绘若用宽幅星（如 150km 幅宽）条带数降至 ~35，但分辨率约 0.5~0.75m 且幅宽越大分辨率越粗，
> 需按用户的分辨率要求选择星座组合。

## 3. 实施计划

| 阶段 | 内容 | 影响面 |
|---|---|---|
| P1 | 重写 `normalizeTaskStrips`：投影建系 + 轨迹方向 + 重叠率控制 | 所有面目标任务 |
| P2 | 新增 `strip_planner.mjs`：尺度判定 + 策略选择 + 同轨拼幅检查 | 新增模块 |
| P3 | 候选表增加条带字段（方位角/经纬度范围/长度/重叠率/有效GSD） | 数据结构 + 前端 |
| P4 | 覆盖计划输出与缺口说明（任务详情页） | 前端 |
| P5 | 回归测试：设施/北京/京津冀三档，与手工计算对账 | 测试 |

## 4. 风险与验证口径

- **所有几何结论必须可独立复核**：投影可逆、条带面积和 ≈ 多边形面积 × (1+重叠冗余)
- **回归基准**：北京全域 12km 幅宽应得 16~17 条带（当前 22 条且外扩 37.5km）
- **不改变**：点目标路径（strips=1）、候选约束、派单流程
- 迁移期双算：新算法上线后对历史任务重算，比对差异
