## 二、数据结构

### satellites 表核心字段

| 字段 | 说明 |
|---|---|
| noradId | NORAD 编号（唯一键，与 CelesTrak 严格对齐） |
| name / intlDesignator | 名称 / 国际编号 |
| gpJson | CelesTrak OMM JSON 原文（SGP4 直接传播的数据源） |
| tle1 / tle2 | 两行 TLE（legacy 卫星保留原库 TLE；gpJson 来源的卫星此字段为占位，传播不走它） |
| epoch | 星历历元（ISO UTC） |
| category / subCategory | 大类（imaging/recon/weather/science）/ 细分（optical/sar/staring/hyperspectral/recon_imaging/meteorological/oceanography/earth_observation） |
| payloadType | 载荷类型中文说明 |
| altitude / inclination / period / eccentricity | 轨道参数（从 MEAN_MOTION 用 μ/n² 三次方根精确计算） |
| country / operator / launchDate / launchSite | 元数据 |
| missionDescription | 任务说明 |
| source | legacy（原工作台迁移）/ celestrak（CelesTrak 实抓） |

### 其他表

- `missions`：成像侦察任务（AOI + 指派卫星 + 状态流转）
- `static_layers`：火点/风场静态示例图层

## 三、数据质量治理记录（本次加固）

1. **轨道高度公式修正**：原近似公式导致高度计算错误（高分一号算出 49000km），改为 a=(μ/n²)^(1/3) 精确计算并全库重算。
2. **原库 NORAD 错配修正（10 处）**：与 CelesTrak SATCAT 逐一交叉核验，修正 USA-245/290(KH-11)、NROL-101/82、YAOGAN-12、YAOGAN-31 01B、ICEYE-X2 的 NORAD 编号；删除 WORLDVIEW-3@38016（真实身份为铱星碎片）与 NROL-71@44481（实为 AEHF-5 通信星）。
3. **假 TLE 清理**：原库中 KH-11/NROL 等 4 颗密级侦察星的 TLE 为模板占位假数据（历元/倾角/偏心率整齐划一），公开渠道无真实星历，按「不编造」原则移除。
4. **星历全量刷新**：94 颗 legacy 卫星的 233 天旧星历全部刷新为 2026-11-04/05 新历元。
5. **元数据补全**：国家归属标准化（统一中文名）、倾角从 TLE/GP 补齐、subCategory/payloadType 全库规范化。

## 四、更新机制

- `python3 scripts/refresh_tle.py check` — 通道探测 + 星历龄期报告
- `python3 scripts/refresh_tle.py plan` — 输出 WebFetch 通道抓取清单
- `python3 scripts/refresh_tle.py fetch` — CelesTrak 直连恢复后全量刷新（限速串行）
- 抓取数据落到 `data/webfetch_raw/<系列>.json`，随后 `node scripts/seed_webfetch.mjs && node scripts/consolidate.mjs` 入库
- **建议**：星历龄期 > 7 天时刷新；> 30 天过境预报误差明显（界面已有龄期提示）

## 五、数据真实性承诺

- 所有 gpJson 均为 CelesTrak 实时抓取原文，历元可溯源（`data/webfetch_raw/` 保留原始抓取文件）；
- 无任何编造/占位星历；密级军事卫星（KH-11、NROL 部分）无公开星历者不入库；
- legacy 数据保留原库的任务描述/运营方等元信息，轨道数据一律以 CelesTrak 新历元为准。
