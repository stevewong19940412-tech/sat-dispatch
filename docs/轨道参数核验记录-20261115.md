# 卫星轨道参数核验记录（2026-11-15）

## 问题

`satellites` 表的 `altitude` 与 `period` 两列，全库 310 颗**全部错误**：

| 字段 | 错误形态 | 实例 |
|---|---|---|
| `altitude` | 约为真实值的 78.8 倍 | GAOFEN-1 存 49285.8，实际 645 |
| `period` | 约为真实值的 0.2 倍 | 存 19.5，实际 97.5 分钟 |
| `apogee` / `perigee` | 全部为空 | — |
| `inclination` | **正确**（比值中位数 1.000），未动 | — |

**业务影响**：`dispatch.mjs` 用 `sat.altitude < 20000` 判定近地轨道，因全部大于 20000 而恒为 false →
直控方案驳回时的「必需轨道高度（requiredAltKm）」诊断永远输出 null，运维看不到「差多少才够拍」。

## 修法

不按倍率反推（各星倍率并非常数），而是**从每颗星自己的 TLE / gpJson 用 SGP4 解析**：
`scripts/fix_orbit_params.mjs`

- 半长轴 `a = satrec.a × 6378.137`（WGS-72 地球半径）
- 高度 `= a − 6371`；远/近地点按偏心率 `a(1±e) − 6371`
- 周期 `= 2π / satrec.no`（rad/min）
- 结果同时写 SQLite 种子库与 PocketBase（310/310 成功）

### GEOEYE-1 的说明（唯一存疑项）

官方记载：GeoEye-1 原在约 681 km，**2013 年夏抬升至 770 km**。库内 682 km 与「抬轨前」一致。
但其 gpJson 纪元为 2026-11-04、`MEAN_MOTION = 14.647` 圈/日，确实对应 682 km。

判定：**这是上游数据源（gpJson）本身的口径问题，不是本项目计算错误**。本脚本以 TLE/gpJson 为唯一权威源，
保持与轨道预报一致（否则「显示高度」与「实际算轨道的值」会打架）。若需修正，应先确认该星当前真实轨道。

## 副产物：TLE 文本截断（已知、不影响功能）

310 颗中有 **233 颗的 `tle1`/`tle2` 只剩 8 个字符**（如 `1 39150U`），真实轨道数据在 `gpJson` 里。
`candidate_calc.mjs` 的 `makeSatrec()` 采用 **gpJson 优先**策略，所以轨道计算正常。
已确认：**0 颗星存在「TLE 截断且无 gpJson」的情况**，即不存在无法计算轨道的星。

```bash
node scripts/fix_orbit_params.mjs             # 写 SQLite 种子库
node scripts/fix_orbit_params.mjs --pb        # 同时同步 PocketBase
```
