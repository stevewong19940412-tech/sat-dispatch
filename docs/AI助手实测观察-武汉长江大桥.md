# AI 下单助手实测观察（武汉长江大桥光学 2m 下单）

测试路径：AI 面板连接 Blade Agent → 自然语言下单 → 四轮选择题确认 → 观察执行

## 表现好的部分

1. **云量真实预报核验**：AI 主动用 open-meteo 发现明天云量 59–100% 超标，指出"系统内置云量模拟场显示 1% 与真实预报不符"——诚实不编造；
2. **逐项选择题确认**（四个）：改期日期（含不推荐项的理由）/ 时间窗 / 优先级与通道（明确"应急会走直控流程并需值班确认"）/ 附加时效；
3. **推荐合理**：11/12–11/14 也全阴（86–100%）→ 推荐 11/19（云量 0–2%、23 候选）；
4. **派单红线部分生效**：AI 说"现在派单"但最终没有执行 dispatch（工程侧防线拦截生效），任务状态没被越权改变。

## 暴露的问题

1. **执行步数巨大且空转**：整个流程跑到 2965 步，其中大量步骤耗在"检查系统→恢复流程"（架构红线没拦住旧端口记忆）和"诊断任务 39 复用"打转；
2. **最终没交付建单**：武汉长江大桥任务始终没有落库——AI 试图"复用诊断任务改名"而不是干净建单，改名执行未成功后流程停在 265 步，用户不推就不动；
3. **"代为确认"话术残留**：AI 提到"你已明确委托下单，因此我按流程代为确认"——与"派单由用户在工作台人工操作"的口径有出入（确认可以代做，但话术应说清楚"确认后任务停在待派单，派单由你人工选择"）。

## 结论

AI 助手的"分析-诚实汇报-选择题确认"链路合格；但"干净建单"的执行链路不可靠（打转+不交付）。
正确用法（当前版本）：AI 用于需求澄清与云量核验，建单仍由用户明确指令驱动（本次我最后一条消息给了明确建单参数，AI 收到后应直接 create——但其选择了复用诊断任务路线，未交付）。
待修复：AI 助手 role_prompt 中补"诊断任务不得改名复用，交付必须新建正式任务"。
